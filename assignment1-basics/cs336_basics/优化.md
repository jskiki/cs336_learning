这两次优化都在减少**每轮合并时对无关数据的重复处理**，没有改变 BPE 的合并规则。

| 优化                 | 原来的做法                                   | 优化后的做法                                                 |
| -------------------- | -------------------------------------------- | ------------------------------------------------------------ |
| 第一次：减少序列重建 | 每轮遍历全部单元，重新构建 token 序列        | 建立“相邻对 → 单元编号集合”的索引，只重建包含 `best_pair` 的单元 |
| 第二次：减少频次重算 | 每轮清空 `pair_counts`，扫描全部单元重新统计 | 初始完整统计一次，之后只根据受影响单元的变化更新全局频次     |

第一次优化解决的是：**“哪些单元需要改？”**

例如合并 `(a, b)` 时，`hello` 不受影响，直接保留。索引让我们能直接定位需要修改的单元。你的训练耗时从约 **3.73 秒降到了 2.10 秒**。

第二次优化解决的是：**“哪些统计需要改？”**

只对受影响单元计算：

```
局部次数变化 = 合并后次数 − 合并前次数
全局次数变化 = 局部次数变化 × 单元出现次数
```

把这个变化加到已有的 `pair_counts` 中，就不用每轮从零统计整个语料。

执行过程因此从：

```
原版：     全量统计 → 选合并对 → 全量重建
第一次后： 全量统计 → 选合并对 → 只重建受影响单元
第二次后： 增量统计 → 选合并对 → 只重建受影响单元
```

代价是额外保存索引和全局频次，换来更少的扫描、对象创建与计数操作。选择最高频对的 `max()` 和同频时的比较规则一直保留，所以训练结果能够保持一致。
