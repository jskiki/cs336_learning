**左上：前向时间花在哪些操作上**

每根柱子代表一个模型和上下文长度，总高度为 100%。

- 蓝色：全部矩阵乘法。

**结论：序列越长，softmax、掩码等操作的占比越大。** 这里是前向 kernel 时间的占比，不是 GPU 利用率。

**右上：完整训练时间花在哪个阶段**

将训练 kernel 时间分为前向、反向、优化器更新和损失计算。

**结论：反向占比最大，约为 61%～69%。** 因此只加速前向，整个训练的提速会受到限制。

**左下：medium 的 softmax 内部耗时**

比较长度 1024 和 2048，将 softmax 分成除法、减去最大值、指数、求最大值与求和。

纵轴是**每遍前向跨 24 层累计的 kernel 时间**：从约 **14.40 ms** 增至 **54.60 ms**。

**结论：长度翻倍后，softmax 耗时接近四倍，而且减法、除法也占了不少时间。**

**右下：开启 Nsight 后，整体计时变化多少**

蓝色是仅前向，红色是完整训练。计算方式为：

\[ \frac{\text{采集时墙钟耗时}-\text{普通运行墙钟耗时}} {\text{普通运行墙钟耗时}}\times100\% \]

**结论：短模型对采集更敏感。** 但这些是不同次运行，差值同时包含运行波动，不能全部视为工具开销。

```python
import torch

s1 = torch.tensor(0, dtype=torch.float32)
for i in range(1000):
    s1 += torch.tensor(0.01, dtype=torch.float32)
print(s1)

s2 = torch.tensor(0, dtype=torch.float16)
for i in range(1000):
    s2 += torch.tensor(0.01, dtype=torch.float16)
print(s2)

s3 = torch.tensor(0, dtype=torch.float32)
for i in range(1000):
    s3 += torch.tensor(0.01, dtype=torch.float16)
print(s3)

s4 = torch.tensor(0, dtype=torch.float32)
for i in range(1000):
    x = torch.tensor(0.01, dtype=torch.float16)
    s4 += x.type(torch.float32)
print(s4)
```

这四段代码都执行了 **1000 次累加**。区别在于两件事：**`0.01` 以什么精度保存，以及累加过程以什么精度进行。**

| 情况   | `0.01` 的类型   | 累加器 `s` 的类型 | 结果      |
| ------ | --------------- | ----------------- | --------- |
| 第一段 | FP32            | FP32              | `10.0001` |
| 第二段 | FP16            | FP16              | `9.9531`  |
| 第三段 | FP16            | FP32              | `10.0021` |
| 第四段 | FP16，再转 FP32 | FP32              | `10.0021` |

**第一段：FP32 输入，FP32 累加**

```
s += torch.tensor(0.01, dtype=torch.float32)
```

FP32 不能精确表示 `0.01`，而每次加法也可能产生舍入。1000 次累加后，得到接近 10 的 `10.0001`。

**第二段：FP16 输入，FP16 累加**

```
s += torch.tensor(0.01, dtype=torch.float16)
```

不仅 `0.01` 被近似表示，**每次累加的结果还必须舍入回 FP16**，累计误差明显增大，最终得到 `9.9531`。

例如，FP16 在 `[8, 16)` 范围内，相邻数间隔为 `0.0078125`，所以加上约 `0.01` 后，实际保存的增量可能只有 `0.0078125`。

**第三段：FP16 输入，FP32 累加**

```
s += torch.tensor(0.01, dtype=torch.float16)
```

FP16 保存的 `0.01` 实际约为：

```
0.01000213623046875
```

加法使用 FP32 精度进行，因此这里主要保留的是**输入量化误差**：

\[ 1000\times0.01000213623046875 =10.00213623046875 \]

显示为 `10.0021`，比第二段准确得多。

**第四段：显式转成 FP32 后累加**

```
x = torch.tensor(0.01, dtype=torch.float16)
s += x.type(torch.float32)
```

它与第三段效果相同：第三段在加法中进行类型提升，第四段显式转换。**转换只能保留 FP16 已经存下来的近似值，不能恢复成精确的 `0.01`**，因此结果同样是 `10.0021`。

这个实验说明：**低精度输入配合高精度累加，可以显著减少累加过程中的误差，但无法消除输入在低精度表示时已经产生的误差。**

### 关于混合精度训练的理解

混合精度训练在一些适合降低精度的计算时会降低精度进行计算，以此来达到加速训练的效果，但是模型的参数保存还是以最开始的设置来保存的如float32，（中间的一些结果有的是以低精度保存的如bfloat16）

#### 关于显存的占用

启用混合精度训练后，显存的变化要看两方面

\[ \text{显存净变化} = \text{转换副本等额外开销} - \text{低精度激活节省的空间} \]

“转换副本等额外开销”：为了低精度计算，新增加的张量

低精度激活节省的空间”：中间结果使用更少的字节保存

1. **参数保持原有类型，是因为 autocast 不会永久修改参数的 dtype。** 保存模型时，按参数当时的 dtype 保存；不是保存操作强制使用 FP32。我们初始化为 FP32，所以保存的权重仍是 FP32。

2. **显存公式是简化分析，不是精确的峰值计算公式。** 建议写成：

   \[ \text{显存净变化} \approx \text{额外副本及临时张量占用} - \text{低精度激活节省的空间} \]

   实际还取决于张量同时存在多久、计算图保留哪些结果，以及峰值发生在哪个阶段。

每组预热 5 步、记录 2 步；推理使用 `eval()` 和 `no_grad()`，完整训练包含前向、损失、反向及我们实现的 AdamW 更新，逐步同步 GPU。BF16 组只开启 autocast，原始参数、参数梯度及 AdamW 的一阶/二阶状态仍为 FP32。

## 问题（b）：两个上下文长度在前向和完整训练中的峰值显存分别是多少？

回答：FP32 的测量结果如下。

| 上下文长度 | 仅前向推理峰值 / GiB | 完整训练峰值 / GiB |
| --- | ---: | ---: |
| 128 | 12.90432 | 51.54268 |
| 2048 | 19.39646 | OOM，无法给出完整步骤峰值 |

这里的“仅前向”是关闭梯度记录的推理，与前文保留计算图的 `--mode forward` 不同，不能直接复用前文的峰值。

**OOM 证据：** FP32 在第一次前向的 softmax 附近申请额外 2 GiB 时失败；补采失败前已达到约 176.15 GiB peak allocated。BF16 能完成第一次前向，但在反向申请额外 2 GiB 时失败，补采失败前约 173.68 GiB peak allocated；这两个值都是未完成执行的下界，不能填进成功峰值表。

原因是当前显式注意力实现会物化多个大小为 `(4,32,2048,2048)` 的张量，FP32 时每个就是 **2 GiB**，训练又需跨 32 层保留部分中间结果。BF16 的 softmax 等计算仍有 FP32 路径，还会保存低精度权重副本，因此并没有消除这次 OOM；本轮没有偷偷缩小 batch 或更换注意力实现。

## 问题（c）：BF16 混合精度是否显著改变峰值显存？

| 上下文长度 | FP32 推理 / GiB | BF16 推理 / GiB | FP32 完整训练 / GiB | BF16 完整训练 / GiB |
| --- | ---: | ---: | ---: | ---: |
| 128 | 12.90432 | 12.91408 | 51.54268 | 51.40601 |
| 2048 | 19.39646 | 17.27830 | OOM | OOM |

回答：L=128 时，BF16 推理峰值约 12.914 GiB，较 FP32 的 12.904 GiB 略高，而完整训练仅从 51.543 降到 51.406 GiB，下降约 **0.27%**，并不显著；L=2048 的推理从 19.396 降到 17.278 GiB，下降约 **10.92%**。短序列完整训练的峰值位于 AdamW 阶段，FP32 参数、梯度和优化器状态占据大部分显存，因此激活降精度未显著降低全步骤峰值；长序列推理的临时激活占比更高，节省更明显。两种精度的 L=2048 完整训练均 OOM，因此无法比较其完成训练时的峰值，更不能据此推断混合精度训练始终省显存。

## 问题（d）：残差流中一个 FP32 激活张量有多大？

## 问题（f）：一个 TransformerBlock 为反向保存多少内存？最大的五项是什么？梯度占多少？

回答：另采集 xl、L=128、batch=4、FP32 的完整训练，启用 `nsys --cuda-memory-usage=true`、PyTorch `emit_nvtx(record_shapes=True)` 及逐块标记；这个独立诊断关闭 CUDA allocator 缓存，使 Nsight 能看到真实 `cudaMalloc/cudaFree` 生命周期，且包含首次 AdamW 状态初始化，不拿它的总峰值或耗时替代上面的稳态结果。以第 16 层为例，按 storage 去重、排除原有参数与 RoPE 缓冲区后，为反向保存的非参数张量共 **174.222656 MiB**，其中 5 MiB 输入已在调用前存在，故新增保存张量为 **169.222656 MiB**；前向结束还留下 5 MiB 输出。最大的五个独立保存结果均为 **20 MiB**，分别来自 FFN 的 W1 投影、sigmoid、SiLU 乘法、W3 投影和 SwiGLU 门控乘法，各占保存张量总量的 **11.48%**，合计 **57.40%**。

| 五个最大的独立保存结果 | 大小 / MiB | 占 174.222656 MiB 的比例 |
| --- | ---: | ---: |
| `W1(x)`：FFN 第一条投影结果 | 20 | 11.48% |
| `sigmoid(W1(x))` | 20 | 11.48% |
| `W1(x) × sigmoid(W1(x))`：SiLU 结果 | 20 | 11.48% |
| `W3(x)`：FFN 另一条投影结果 | 20 | 11.48% |
| `SiLU(W1(x)) × W3(x)`：门控结果 | 20 | 11.48% |

# 3.2 激活检查点

## 检查点设置理论分析

**如果以完整的 TransformerBlock 为分组单位，理论上应每层单独设置一个 checkpoint。** 原因是：这里一层内部的残差远大于保存一个层输入的开销。

设：

- \(N=32\)：模型层数。
- \(k\)：每个 checkpoint 包裹的层数。
- \(C\)：一个检查点输入的大小。
- \(R\)：一层反向传播所需的残差大小。

不允许嵌套时，需要长期保存约 \(N/k\) 个检查点；反向传播时，还需要重算当前分组，临时保存约 \(k\) 层的残差。因此，峰值激活显存可以粗略建模为：

\[ M(k)\approx \underbrace{\frac{N}{k}C}_{\text{检查点输入}} +\underbrace{kR}_{\text{当前分组的残差}} \]

这里忽略了张量共享、梯度和临时工作空间等细节，因此这个式子用于判断趋势，不能代替实测。

对于题目中的 FP32 输入：

\[ C=4\times2048\times2560\times4\text{ bytes} =80\text{ MiB} \]

采用教材中对 `torch.compile` 融合后单层残差的示例测量值（并非下面本地实现的单层实测值）：

\[ R\approx3651.31\text{ MiB} \]

将 \(k\) 暂时视为连续变量，对 \(M(k)\) 求最小值：

\[ M'(k)=-\frac{NC}{k^2}+R=0 \]

得到：

\[ k^*=\sqrt{\frac{NC}{R}} =\sqrt{\frac{32\times80}{3651.31}} \approx0.84 \]

由于整层分组要求 \(k\ge1\)，所以应选择 **\(k=1\)**。用同一个粗略模型比较：

| 每组层数 \(k\) | 保存的检查点 | 当前分组残差 | 合计        |
| -------------- | ------------ | ------------ | ----------- |
| 1              | 2560 MiB     | 3651.31 MiB  | 约 6.07 GiB |
| 2              | 1280 MiB     | 7302.62 MiB  | 约 8.38 GiB |

从每组一层改成两层，虽然减少了约 **1.25 GiB** 的检查点存储，却增加了约 **3.57 GiB** 的残差存储，因此这个近似模型预测峰值反而升高；实际最优粒度仍需通过不同分组大小的实验验证。

## 逐层检查点与无检查点基线对比（2026-11-16）

配置：B200、FP32，XL（32 层、16 头、d_model=2560、d_ff=10240），batch=4、序列长度=2048、词表=10000。测量前向＋反向，不含优化器更新，未启用 compile 或混合精度。

逐层 checkpoint 使用 `use_reentrant=False`，无嵌套；预热 2 步、测量 3 步，预热后重置显存峰值统计。

| 方案 | 结果 | 峰值 allocated / GiB | 每步耗时 / ms（均值 ± 标准差） |
| --- | --- | ---: | ---: |
| 无 checkpoint | OOM | — | — |
| 每层一个 checkpoint | 成功 | **33.254** | **4546.840 ± 0.342** |

**逐层 checkpoint 通过反向重计算减少激活保存，使该配置从 OOM 变为可运行。** 对照组 OOM，无法计算精确的显存节省率或耗时增幅；尚未比较相邻块大小，因此本轮不证明最优分组粒度。

**1. 专家怎样放到不同 GPU？**

假设一个 MoE 层有 4 个专家，使用两张 GPU：

```
GPU 0：专家 E₀、E₁
GPU 1：专家 E₂、E₃
```

在这个基本配置中，每张卡保存自己负责专家的完整参数及相关训练状态，不需要保存其他专家的完整副本。

如果单个专家也很大，还可以结合 TP，将一个专家内部的矩阵计算继续拆分。[DeepSpeed 专家并行配置](https://www.deepspeed.ai/tutorials/mixture-of-experts/)

**2. 前向传播：token 去找专家**

假设两张卡最初各有一个 token，使用 Top-2 路由：

```
GPU 0 的 token A → 专家 E₀、E₂
GPU 1 的 token B → 专家 E₁、E₂
```

执行过程如下。

**第一步：路由。**

Router 根据 token 的隐藏向量，计算目标专家和对应权重。

**第二步：分发（Dispatch）。**

```
token A：
  发给 GPU 0 的 E₀，本地处理
  发给 GPU 1 的 E₂，跨卡发送

token B：
  发给 GPU 0 的 E₁，跨卡发送
  发给 GPU 1 的 E₂，本地处理
```

传输的主要是 token 的隐藏向量及必要的路由信息，而不是把专家权重搬到 token 所在的卡。

**第三步：专家计算。**

```
GPU 0：
  E₀ 处理 A
  E₁ 处理 B

GPU 1：
  E₂ 批量处理 A、B
  E₃ 本次没有任务
```

实际实现会把发往同一专家的 token 组织成批次，进行矩阵计算。

**第四步：返回并合并（Combine）。**

专家输出返回原来负责该 token 的位置，然后按路由权重组合：

\[ y_A=\alpha_0E_0(x_A)+\alpha_2E_2(x_A) \]\[ y_B=\beta_1E_1(x_B)+\beta_2E_2(x_B) \]

结果恢复为原本的 token 顺序，进入后续网络。

多卡分发和回收常使用 **All-to-All** 或专门优化的通信实现。**All-to-All 不意味着每个 token 都发给全部 GPU；token 只需要送往选中专家所在的位置。** [DeepSeek-V3 通信实现](https://arxiv.org/html/2412.19437v2)

**3. 反向传播怎么做？**

反向沿前向的数据路径返回：

```
token 原位置获得输出梯度
            ↓
根据路由权重，把梯度发给选中的专家
            ↓
各专家计算：
  ① 自己的参数梯度
  ② 对 token 输入的梯度贡献
            ↓
输入梯度贡献返回 token 原位置
            ↓
合并贡献，继续向前面的网络反向传播
```

同一个 token 经过多个专家，其输入梯度需要汇总各专家路径的贡献；完整反向还需要计入 Router 对该 token 的依赖所产生的梯度。

不同专家拥有不同参数，因此 **不能把 E₀ 的参数梯度与 E₂ 的参数梯度相加**。每个专家使用分配给自己的 token 贡献的梯度更新参数。

如果同一个专家还有数据并行副本，则需要在这些副本之间同步梯度。

**4. EP 与 TP、PP 有什么区别？**

| 方式     | 拆分什么                     | token 如何参与计算          |
| -------- | ---------------------------- | --------------------------- |
| **EP**   | 同一 MoE 层的不同专家        | 路由到少数被选中的专家      |
| **TP**   | 一个层或专家内部的矩阵计算   | 多张 GPU 合作完成同一个算子 |
| **PP**   | 模型的不同层                 | token 依次经过多个阶段      |
| **FSDP** | 参数、梯度、优化器状态的存储 | 按需收集当前模块参数后计算  |

EP 的特点是：**计算任务分配随 token 的路由结果动态变化**，不是固定让所有 token 经过全部专家。

**5. EP 的主要收益和瓶颈**

**收益是专家存储可以分散。** 增加专家数量时，可以用更多 GPU 容纳参数，而每个 token 仍只激活少数专家。

但运行效率主要受三个因素影响：

- **负载不均衡**：热门专家忙，其他专家空闲，整批计算可能被最忙的专家拖慢。
- **通信开销**：token 分发和结果返回需要搬运激活值，跨节点时成本尤其明显。
- **专家批次过小**：每个专家只收到少量 token 时，矩阵计算可能难以充分利用 GPU。

因此，实际系统通常结合负载均衡路由、专家放置、批量计算，以及通信计算重叠来提高效率。[DeepSeek-V3 的专家并行与调度设计](https://arxiv.org/html/2412.19437v2)

### 梯度计算与all_reduce异步

每个 rank 都有一份参数，也各自算出一份**本地梯度**。钩子只负责通知当前 rank「我的梯度准备好了」。**等其他 rank 参与同一次归约，是 all-reduce 自己负责的。**

`register_post_accumulate_grad_hook` 是**参数张量的方法**，接收一个参数 `hook`，也就是你想让 PyTorch 自动调用的函数。

```
handle = parameter.register_post_accumulate_grad_hook(on_grad_ready)
```

回调函数的签名是 `hook(param: torch.Tensor) -> None`。当 `backward()` 更新了这个参数的 `.grad`，PyTorch 就会调用 `on_grad_ready(parameter)`。所以回调里收到的是**参数本身**，用 `param.grad` 读取或原地修改梯度。注册时写 `on_grad_ready`，表示把函数交给 PyTorch，留到反向传播时调用。[PyTorch 文档](https://docs.pytorch.org/docs/stable/generated/torch.Tensor.register_post_accumulate_grad_hook.html)

常见用途有三种：

- **观察梯度**，比如记录梯度的形状或范数。
- **修改梯度**，比如用 `param.grad.mul_(0.5)` 把这个参数的梯度缩小一半。
- **发起 DDP 通信**，比如在回调里对 `param.grad` 调用 `dist.all_reduce(..., async_op=True)`，把返回的通信句柄保存起来。

在 DDP 类里，可以直接把**绑定方法**传进去：

```
handle = parameter.register_post_accumulate_grad_hook(self._on_grad_ready)
```

如果 `_on_grad_ready` 定义成 `def _on_grad_ready(self, param):`，Python 会自动绑定 `self`，PyTorch 只需要传入 `param`。这样回调既能访问 `param.grad`，也能把通信句柄存到 `self` 上。

注册一次后，后续每次反向传播只要更新了这个参数的 `.grad`，回调就会触发。需要取消时，调用注册返回的 `handle.remove()`。

前两种时间接近，主要是因为**展平减少了通信调用次数，但两种方式要归约的梯度总量相同**，而且展平本身也有开销。

| 指标       | 逐参数 all-reduce | 展平后一次 all-reduce | 降幅  |
| ---------- | ----------------- | --------------------- | ----- |
| 梯度同步   | 37.092 ms         | 35.893 ms             | 3.23% |
| 完整训练步 | 564.963 ms        | 561.013 ms            | 0.70% |

有三个原因：

1. **XL 的梯度数据本身很大。** 每张卡约有 34 亿个 FP32 梯度元素，合计约 **13.6 GB**。仅一个 `2560 × 10240` 的权重矩阵，其梯度就约有 **105 MB**。逐参数版虽然调用次数多，但其中不少调用处理的是大张量，合并调用主要省下的是每次发起通信的固定开销。
2. **展平增加了 GPU 内存读写。** `torch.cat` 要把原梯度拷进连续缓冲区，归约完成后，`copy_()` 又要把平均后的梯度写回各参数。我们的同步计时包含这两步，所以它们会抵消一部分合并通信带来的收益。
3. **梯度同步只占原来整步的 6.57%。** 两种方式都在反向结束后才同步，前向、反向和优化器更新仍占大部分时间。同步阶段只省下约 **1.2 ms**，整步改善自然有限。

作业实现与 ZeRO Stage 1（\(P_{\mathrm{os}}\)）都在数据并行 rank 之间分摊优化器状态，并在各 rank 保留完整模型权重。作业实现先对完整梯度做 all-reduce，并在本地更新后逐参数广播权重。通信优化版 ZeRO Stage 1 将归约后的梯度直接交给负责更新的 rank，再 all-gather 新权重，按双卡、权重和梯度同精度的有效传输量估算，作业实现约为普通 DDP 的 **1.5 倍**，通信优化版约为 **1 倍**。[ZeRO 论文 §5.1 与 §7](https://arxiv.org/pdf/1910.02054#page=10) · [DeepSpeed ZeRO-1 通信优化](https://www.deepspeed.ai/2020/03/17/reduce-scatter.html)

| 方案                            | 梯度同步                                                 | 更新后的权重                                 |
| ------------------------------- | -------------------------------------------------------- | -------------------------------------------- |
| ZeRO-0 / 普通 DDP               | `all_reduce`，每个 rank 拿到完整的平均梯度               | 各 rank 都更新完整模型                       |

| 通信优化版 ZeRO-1               | `reduce_scatter`，每个 rank 只拿到自己要用的平均梯度分片 | 各 rank 更新自己的分片，再 `all_gather` 权重 |

# 8 并行策略分析

## 8.1 通信原语

设有 \(N\) 个 rank，编号 \(0,\ldots,N-1\)，单个完整张量大小为 \(S\) 字节，每个 rank 的出站带宽为 \(W\) 字节/秒。环上 rank \(i\) 向 \((i+1)\bmod N\) 发送，从 \((i-1)\bmod N\) 接收。题设的理想模型只计传输时间。同一轮中各 rank 同时发送和接收，所以每轮按单个 rank 发送的字节数除以 \(W\) 计时。

### All-reduce 完成的操作

求和版 `all_reduce(SUM)` 对所有 rank 的输入张量逐元素求和，并让每个 rank 都得到同一个完整结果 \(y=\sum_{i=0}^{N-1}x^{(i)}\)。例如三张卡分别持有 `[1, 2]`、`[3, 4]`、`[5, 6]`，归约后每张卡都得到 `[9, 12]`，输出形状与单卡输入相同。数据并行训练时，各 rank 先算本地梯度，再通过 all-reduce 取得全局梯度和，随后除以 rank 数得到平均梯度。

### 环形 all-gather

每个 rank 起初持有一个大小为 \(S/N\) 字节的分块。第 1 轮发送自己的分块，后续每轮转发上一轮收到的分块，并将收到的分块保存在本地。经过 \(N-1\) 轮，每个 rank 都拼出完整张量。每轮发送 \(S/N\) 字节，因此耗时为 \(\frac{N-1}{N}\frac{S}{W}\)。

### 环形 reduce-scatter

每个 rank 都从完整张量 \(x^{(i)}\) 开始，将它切成 \(N\) 块。\(x_j^{(i)}\) 表示 rank \(i\) 对第 \(j\) 块的贡献，目标是让 rank \(j\) 得到 \(y_j=\sum_{i=0}^{N-1}x_j^{(i)}\)。沿环传递的是一个分块的部分和，接收端加上自己的同编号分块，下一轮继续转发更新后的部分和。

第 \(t\) 轮，rank \(i\) 发送第 \((i-t)\bmod N\) 块。左邻居是 \((i-1)\bmod N\)，代入同一发送公式可知 rank \(i\) 收到第 \((i-t-1)\bmod N\) 块。这也正是 rank \(i\) 下一轮发送的编号。最后一轮 \(t=N-1\)，收到的编号是 \(i\)，此时加上本机贡献就得到完整的 \(y_i\)。

以 4 张卡为例，第 0 块从 GPU 1 出发，沿 \(1\to2\to3\to0\) 走 3 跳。GPU 2 和 GPU 3 依次加上自己的第 0 块，GPU 0 加上最后一份贡献，得到 \(y_0\)。其他三块同时沿环进行同样的归约。每轮每个 rank 发送一个大小为 \(S/N\) 字节的分块，共 \(N-1\) 轮，因此耗时为 \(\frac{N-1}{N}\frac{S}{W}\)。

### 标准环形 all-reduce

先用环形 reduce-scatter，让每个 rank 得到负责的归约结果分块。再用环形 all-gather，让每个 rank 收齐所有结果分块。两阶段各走 \(N-1\) 轮，每轮发送 \(S/N\) 字节，总耗时为 \(2\frac{N-1}{N}\frac{S}{W}\)。

### 环形全归约的另一种实现（`alternate_ring_all_reduce`）

每个 rank 将本地部分和初始化为自己的完整张量。第 1 轮发送自己的原始张量，后续每轮发送上一轮收到的原始张量。接收时，将收到的张量逐元素加到本地部分和，同时保留该原始张量供下一轮转发。以 4 张卡为例，GPU 0 在第 1 轮收到 \(x^{(3)}\)，本地部分和变成 \(x^{(0)}+x^{(3)}\)。第 2 轮它转发 \(x^{(3)}\)，并接收 \(x^{(2)}\) 加入本地部分和。

第 \(t\) 轮开始前，rank \(i\) 持有的待转发张量已经沿环走了 \(t-1\) 跳，因此来源是 \((i-t+1)\bmod N\)。同一轮从左邻居收到的张量来源是 \((i-t)\bmod N\)。随着 \(t\) 从 1 到 \(N-1\)，每个 rank 恰好收到其他所有 rank 的原始张量各一次，加上初始化时已有的本地贡献，最终每个 rank 都得到完整的张量和。

这种实现每轮发送一个大小为 \(S\) 字节的完整张量，单轮耗时 \(S/W\)，因此总耗时为 \(\boxed{(N-1)\frac{S}{W}}\)。

## 8.2 数据并行分析

### 题目 `data_parallel_calcs`（3 分）

考虑单个门控 FFN。输入 \(x\) 的形状为 \((B,D)\)，\(W_1,W_2\) 的形状为 \((D,D_{\mathrm{FF}})\)，\(W_3\) 的形状为 \((D_{\mathrm{FF}},D)\)。前向计算为 \(x_1=xW_1\)、\(x_2=xW_2\)、\(z=f(x_1)\odot x_2\)、\(y=zW_3\)，其中 \(f\) 为逐元素激活函数，\(\odot\) 表示逐元素乘法。

使用 \(N_{\mathrm{DP}}\) 个 rank 沿批次维均分 \(B\) 行输入，每个 rank 保留完整权重，并独立完成前向和本地反向计算；权重梯度通过 all-reduce 跨 rank 求和。设每卡计算速度为 \(C\) FLOP/s，出站带宽为 \(W\) 字节/秒。题设使用 FP16 权重与激活，下面按每个梯度元素也用 FP16 传输来计算。假设计算和通信可以完全重叠，当通信时间超过计算时间时，通信成为瓶颈。

1. **（a）** 使用 \(N_{\mathrm{DP}}\) 路数据并行时，每卡反向传播需要多少 FLOPs？只计矩阵乘法。
2. **（b）** 反向传播需要多少通信时间？
3. **（c）** 固定其他量时，\(N_{\mathrm{DP}}\) 多大才会进入通信瓶颈？用一个关于 \(N_{\mathrm{DP}}\) 的不等式表示可用范围。

### 单层 FFN 的推导

**（a）计算量。** 本地反向先算 \(dz=dyW_3^\top\)，再逐元素计算 \(dx_2=dz\odot f(x_1)\) 与 \(dx_1=dz\odot f'(x_1)\odot x_2\)。输入梯度 \(dx=dx_1W_1^\top+dx_2W_2^\top\) 用两次矩阵乘法，权重梯度 \(dW_3=z^\top dy\)、\(dW_2=x^\top dx_2\)、\(dW_1=x^\top dx_1\) 各用一次。算上 \(dz\) 共六次矩阵乘法，每次耗费 \(2(B/N_{\mathrm{DP}})DD_{\mathrm{FF}}\) FLOPs，因此每卡反向计算量为

\[
F_{\mathrm{GPU}}=\boxed{\frac{12BD D_{\mathrm{FF}}}{N_{\mathrm{DP}}}}.
\]

**（b）通信时间。** 每个本地权重梯度对 \(B/N_{\mathrm{DP}}\) 个输入行的贡献求和，形状仍与相应权重相同。三个梯度各有 \(DD_{\mathrm{FF}}\) 个元素，按 FP16 合计 \(6DD_{\mathrm{FF}}\) 字节。用标准环形 all-reduce 归约这三份梯度，得到

\[
T_{\mathrm{comm}}=\boxed{12\frac{N_{\mathrm{DP}}-1}{N_{\mathrm{DP}}}\frac{DD_{\mathrm{FF}}}{W}}.
\]

**（c）设备数上限。** 每卡计算时间为 \(T_{\mathrm{comp}}=F_{\mathrm{GPU}}/C\)。代入 \(T_{\mathrm{comm}}\le T_{\mathrm{comp}}\)，两边约去 \(12DD_{\mathrm{FF}}/N_{\mathrm{DP}}\)，得到

\[
\frac{N_{\mathrm{DP}}-1}{W}\le\frac{B}{C}
\quad\Longrightarrow\quad
\boxed{N_{\mathrm{DP}}\le 1+\frac{BW}{C}}.
\]

固定 \(B\) 时，增加设备会按 \(1/N_{\mathrm{DP}}\) 降低每卡的矩阵乘法量，而每卡参与归约的梯度张量大小由权重决定。

### 套用到仓库的 `TransformerLM`

现在 \(B\) 表示全局序列数，\(T\) 表示实际序列长度，\(N=N_{\mathrm{DP}}\)，每卡处理 \(BT/N\) 个 token。另记 \(L\) 为 Transformer 层数、\(V\) 为词表大小。按仓库里的稠密注意力实现，每个 head 先计算完整的 \(T\times T\) 分数矩阵，再应用 causal mask，因此矩阵乘法按完整矩阵计数。词嵌入是查表，梯度计入通信量。下面只计矩阵乘法，并按关闭激活检查点的 DDP benchmark 口径计算。 [注意力实现](../cs336-basics/cs336_basics/attention.py#L40) · [词嵌入实现](../cs336-basics/cs336_basics/layers.py#L119) · [模型构建](../cs336_systems/benchmark_ddp.py#L116)

| 模块 | 每 token 的反向矩阵乘法 FLOPs |
| --- | ---: |
| 每层 Q、K、V 和输出投影 | \(16D^2\) |
| 每层 \(QK^\top\) 和注意力概率与 \(V\) 矩阵的乘积 | \(8TD\) |
| 每层 SwiGLU 的三个线性层 | \(12DD_{\mathrm{FF}}\) |
| 整模型的 LM head | \(4DV\) |

每个线性层的反向各用一次矩阵乘法计算输入梯度和权重梯度。注意力核心的两个前向乘积各对应两个反向矩阵乘法，合计四次。在所有 head 上相加后，每条序列贡献 \(8T^2D\) FLOPs，因此每 token 为 \(8TD\)。整模型每卡反向计算量为

\[
F_{\mathrm{tok}}=L(16D^2+8TD+12DD_{\mathrm{FF}})+4DV,
\qquad F_{\mathrm{GPU}}=\frac{BT}{N}F_{\mathrm{tok}}.
\]

每层参数包含四个注意力投影、三个 SwiGLU 权重矩阵和两个 RMSNorm 权重。模型还有独立的词嵌入和 LM head，以及最后一个 RMSNorm。设每个梯度元素占 \(s\) 字节，普通 DDP 同步全部 \(P\) 个参数的梯度。 [模型参数定义](../cs336-basics/cs336_basics/transformer_lm.py#L80) · [Transformer block](../cs336-basics/cs336_basics/transformer_block.py#L68) · [DDP 梯度同步](../cs336_systems/ddp.py#L22)

\[
P=L(4D^2+3DD_{\mathrm{FF}}+2D)+2VD+D,
\qquad T_{\mathrm{comm}}=2\frac{N-1}{N}\frac{sP}{W}.
\]

将 \(T_{\mathrm{comm}}\) 与 \(T_{\mathrm{comp}}=BT F_{\mathrm{tok}}/(NC)\) 比较，得到理想带宽模型下的设备数上限

\[
\boxed{N_{\mathrm{DP}}\le 1+\frac{BT F_{\mathrm{tok}}W}{2sPC}}.
\]

固定模型和全局序列数 \(B\) 时，增大 \(T\) 会增加本地反向计算量，而梯度数据量 \(sP\) 由模型参数和通信精度决定。

**双 B200 的 XL 配置。** \(B=4\)、\(T=512\)、\(N=2\)、\(L=32\)、\(D=2560\)、\(D_{\mathrm{FF}}=10240\)、\(V=10000\)。模型共有 **3,406,809,600** 个参数，每卡处理 1024 个 token，按矩阵乘法估算反向约 **14.19 TFLOP**。benchmark 直接同步 FP32 梯度，取 \(s=4\)。双卡时环形系数 \(2(N-1)/N=1\)，每卡发送量为 **12.69 GiB**。 [XL benchmark 配置与测量](../results/b200-ddp/overlap-ddp-b200.json)

## 8.3 全分片数据并行分析

### FSDP 的前向与反向流程

沿用第 8.2 节的单层门控 FFN，记 \(N=N_{\mathrm{FSDP}}\)。每卡处理 \(B/N\) 行输入，平时只持有优化器状态、梯度和权重各自的分片。三个权重矩阵各有 \(DD_{\mathrm{FF}}\) 个元素，每卡保存每个矩阵的 \(DD_{\mathrm{FF}}/N\) 个元素。

- **前向。** 使用每个完整权重前，先通过 all-gather 收集其分片，再对本地批次执行与 DP 相同的前向计算。用完后释放临时恢复的完整权重。
- **反向。** 再次 all-gather 恢复反向所需的权重，然后根据本地批次计算输入梯度和权重梯度。最后用 reduce-scatter 对各卡的权重梯度求和，并把对应的梯度分片交给各权重分片的持有者。

对任意一个权重矩阵，设 \(G^{(j)}\) 是 rank \(j\) 算出的本地梯度。它覆盖完整权重矩阵，累计的是本地批次的贡献。reduce-scatter 后，rank \(i\) 得到 \(\left[\sum_{j=0}^{N-1}G^{(j)}\right]_i\)，也就是全局求和结果的第 \(i\) 个权重分片。

### 题目 `fsdp_calcs`（3 分）

沿用题目的理想带宽模型，\(C\) 为单卡计算速度（FLOP/s），\(W\) 为单卡出站带宽（字节/秒）。通信中的权重和梯度均按 FP16 计，每个元素占 2 字节。按题设，计算和通信可以完全重叠。

#### （a）每卡反向和前向各需要多少 FLOPs？

每次矩阵乘法涉及 \(B/N\)、\(D\) 和 \(D_{\mathrm{FF}}\) 三个维度，单次耗费 \(2(B/N)DD_{\mathrm{FF}}\) FLOPs。

- **反向**需要六次矩阵乘法，其中 \(dz\) 一次、\(dx\) 两次、三个权重梯度各一次，因此 \(F_{\mathrm{bwd}}=\boxed{12BDD_{\mathrm{FF}}/N}\)。
- **前向**需要 \(xW_1\)、\(xW_2\) 和 \(zW_3\) 三次矩阵乘法，因此 \(F_{\mathrm{fwd}}=\boxed{6BDD_{\mathrm{FF}}/N}\)。

#### （b）每卡反向和前向各需要多少通信时间？

三个完整权重合计 \(6DD_{\mathrm{FF}}\) 字节，三个完整梯度的总大小也相同。由第 8.1 节，环形 all-gather 和环形 reduce-scatter 各需 \(N-1\) 轮传输，每轮发送完整张量大小的 \(1/N\)。

- **反向**包含一次权重收集和一次梯度归约散播，分别覆盖三个矩阵，耗时合计 \(T_{\mathrm{comm,bwd}}=\boxed{12\frac{N-1}{N}\frac{DD_{\mathrm{FF}}}{W}}\)。
- **前向**只需收集三个权重，耗时合计 \(T_{\mathrm{comm,fwd}}=\boxed{6\frac{N-1}{N}\frac{DD_{\mathrm{FF}}}{W}}\)。

#### （c）反向和前向各允许扩展到多少台设备？

分别用通信时间与该阶段的计算时间 \(F/C\) 比较。

\[
\begin{aligned}
\text{反向}\quad
12\frac{N-1}{N}\frac{DD_{\mathrm{FF}}}{W}
&\le \frac{12BDD_{\mathrm{FF}}}{NC}
&&\Longrightarrow\quad \boxed{N_{\mathrm{FSDP}}\le 1+\frac{BW}{C}},\\
\text{前向}\quad
6\frac{N-1}{N}\frac{DD_{\mathrm{FF}}}{W}
&\le \frac{6BDD_{\mathrm{FF}}}{NC}
&&\Longrightarrow\quad \boxed{N_{\mathrm{FSDP}}\le 1+\frac{BW}{C}}.
\end{aligned}
\]

在这个简化模型中，反向的计算量和通信量都恰好是前向的两倍，所以两阶段得到相同的设备数上限。

### 套用到仓库的 `TransformerLM`

沿用第 8.2 节的记号，\(B\) 是全局序列数，\(T\) 是序列长度，\(L\) 是 Transformer 层数，\(V\) 是词表大小。仓库的 FSDP 将 `Linear` 和 `Embedding` 的权重展平后切分，RMSNorm 权重在各卡保留一份。记线性层、词嵌入、全部分片参数与复制参数的元素数分别为

\[
\begin{aligned}
P_{\mathrm{lin}} &= L(4D^2+3DD_{\mathrm{FF}})+VD, &
P_{\mathrm{emb}} &= VD,\\
P_{\mathrm{shard}} &= P_{\mathrm{lin}}+P_{\mathrm{emb}}, &
P_{\mathrm{rep}} &= (2L+1)D.
\end{aligned}
\]

\(P_{\mathrm{lin}}\) 中的 \(VD\) 来自独立的 LM head。双卡 XL 模型里所有分片参数都能均分。对任意 \(N\)，若某个权重的 \(p\) 个元素无法均分，通信时该张量按补齐后的 \(N\lceil p/N\rceil\) 个元素计算。 [FSDP 分片与填充](../cs336_systems/fsdp.py#L73) · [词嵌入与 LM head 定义](../cs336-basics/cs336_basics/transformer_lm.py#L80)

#### （a）整模型每卡反向和前向 FLOPs

每卡仍对 \(BT/N\) 个本地 token 执行完整模型计算。前向的线性层合计每 token \(2P_{\mathrm{lin}}\) FLOPs，稠密注意力的两个乘积合计每 token \(4LTD\) FLOPs。关闭激活检查点并只计矩阵乘法时，每个前向乘积都对应两个反向乘积。设每 token 前向计算量为 \(F_{\mathrm{tok}}^{\mathrm{fwd}}\)，则

\[
F_{\mathrm{tok}}^{\mathrm{fwd}}=2P_{\mathrm{lin}}+4LTD,\qquad
F_{\mathrm{GPU}}^{\mathrm{fwd}}=\frac{BT}{N}F_{\mathrm{tok}}^{\mathrm{fwd}},\qquad
F_{\mathrm{GPU}}^{\mathrm{bwd}}=2F_{\mathrm{GPU}}^{\mathrm{fwd}}.
\]

#### （b）实际通信对象和通信时间

| 阶段 | 集合通信 | 涉及的参数元素数 |
| --- | --- | ---: |
| 前向 | all-gather 线性层和词嵌入的权重 | \(P_{\mathrm{shard}}\) |
| 反向 | all-gather 求输入梯度所需的线性层权重 | \(P_{\mathrm{lin}}\) |
| 反向 | reduce-scatter 全部分片参数的梯度 | \(P_{\mathrm{shard}}\) |
| 梯度同步收尾 | all-reduce 复制的 RMSNorm 梯度 | \(P_{\mathrm{rep}}\) |

词嵌入前向需要完整权重来查表。它的反向根据 token 索引把上游梯度累加到对应行，只需保存索引和权重形状，因而无需再次 all-gather 词嵌入权重。线性层反向用到权重，FSDP 在恢复 autograd 保存的权重视图时发起 all-gather。 [词嵌入查表](../cs336-basics/cs336_basics/layers.py#L119) · [保存权重视图](../cs336_systems/fsdp.py#L162) · [反向权重收集](../cs336_systems/fsdp.py#L215)

设 all-gather 每个权重元素发送 \(s_w\) 字节。benchmark 的 FP32 模式取 \(s_w=4\)，BF16 模式取 \(s_w=2\)。两种模式的 reduce-scatter 都先把梯度转换为 FP32 主权重的 dtype，复制的 RMSNorm 梯度也以 FP32 all-reduce。把反向后的梯度同步收尾计入反向，按均分和标准环形模型得到

\[
\begin{aligned}
S_{\mathrm{fwd}} &= s_wP_{\mathrm{shard}}, &
T_{\mathrm{comm}}^{\mathrm{fwd}} &= \frac{N-1}{N}\frac{S_{\mathrm{fwd}}}{W},\\
S_{\mathrm{bwd}} &= s_wP_{\mathrm{lin}}+4P_{\mathrm{shard}}+8P_{\mathrm{rep}}, &
T_{\mathrm{comm}}^{\mathrm{bwd}} &= \frac{N-1}{N}\frac{S_{\mathrm{bwd}}}{W}.
\end{aligned}
\]

RMSNorm 项的系数 8 来自每元素 4 字节，再乘标准环形 all-reduce 的两个阶段。实际时间线还取决于逐层预取、梯度何时就绪和每次集合通信的启动开销。 [混合精度设置](../cs336_systems/benchmark_fsdp.py#L83) · [权重收集 dtype](../cs336_systems/fsdp.py#L115) · [梯度同步 dtype](../cs336_systems/fsdp.py#L251)

#### （c）整模型的设备数上限

按题目的重叠模型，对每个阶段要求 \(T_{\mathrm{comm}}\le T_{\mathrm{comp}}=F_{\mathrm{GPU}}/C\)，得到

\[
\begin{aligned}
\text{前向}\qquad&\boxed{N_{\mathrm{FSDP}}\le 1+\frac{BT F_{\mathrm{tok}}^{\mathrm{fwd}}W}{C S_{\mathrm{fwd}}}},\\
\text{反向}\qquad&\boxed{N_{\mathrm{FSDP}}\le 1+\frac{2BT F_{\mathrm{tok}}^{\mathrm{fwd}}W}{C S_{\mathrm{bwd}}}}.
\end{aligned}
\]

分片均分时，整个训练步要同时满足这两个条件，取较小的上限。

#### 双 B200 的 XL 配置

\(B=4\)、\(T=512\)、\(N=2\)、\(L=32\)、\(D=2560\)、\(D_{\mathrm{FF}}=10240\)、\(V=10000\)。由此得到 \(P_{\mathrm{lin}}=3{,}381{,}043{,}200\)、\(P_{\mathrm{emb}}=25{,}600{,}000\)、\(P_{\mathrm{rep}}=166{,}400\)，合计 \(3{,}406{,}809{,}600\) 个参数，与 benchmark 记录一致。每卡前向约 **7.10 TFLOP**，反向约 **14.19 TFLOP**。 [XL FSDP benchmark 配置](../results/b200-fsdp/nsight/fsdp-xl.json)

| 通信精度 | 单卡前向发送量（GiB） | 单卡反向发送量（GiB） |
| --- | ---: | ---: |
| FP32 benchmark 配置 | 6.35 | 12.64 |
| 相同 XL 配置下的 BF16 权重收集估算 | 3.17 | 9.49 |

按环形模型估算，FP32 下前向和反向的计算与通信比例基本相同。切换到 BF16 权重收集后，前向通信量减半，反向仍包含 FP32 的梯度通信。在两阶段采用相同 \(C\) 和 \(W\) 的模型下，此时反向的设备数上限更低。

## 8.4 张量并行分析

TP 把一次矩阵乘法分给多个 rank，每卡用自己的权重分片计算。FSDP 沿批次分摊计算，用到当前层时先恢复完整权重，再计算本地样本。

对于 \(xW\)，**列并行**沿 \(W\) 的输出维度切分。各 rank 读取同一份输入，分别计算不同的输出特征，需要完整输出时用 all-gather 拼接。**行并行**沿 \(W\) 的输入维度切分，每个 rank 取对应的输入特征。各 rank 的结果都有完整输出形状，每个元素只含部分输入特征的贡献，通过 all-reduce 求和。

本题的 FFN 让 \(W_1,W_2\) 列并行，在相同位置切分中间特征。门控 \(f(x_1)\odot x_2\) 是逐元素运算，可以在每个 rank 上独立执行。\(W_3\) 行并行，输入分片与门控输出对齐，因此可以直接继续用分片做本地矩阵乘法，最后做一次 all-reduce。记 \(p=N_{\mathrm{TP}}\)，前向为

\[
\begin{aligned}
x_1^{(i)}&=xW_1^{(i)}, &x_2^{(i)}&=xW_2^{(i)},\\
z^{(i)}&=f(x_1^{(i)})\odot x_2^{(i)}, &y^{(i)}&=z^{(i)}W_3^{(i)},\\
y&=\operatorname{all\!-\!reduce}_{\mathrm{TP}}\!\left(\{y^{(i)}\}_{i=0}^{p-1}\right).
\end{aligned}
\]

其中 \(x_1^{(i)},x_2^{(i)},z^{(i)}\) 的形状为 \((B,D_{\mathrm{FF}}/p)\)，每份部分输出 \(y^{(i)}\) 的形状为 \((B,D)\)。仓库的 SwiGLU 按其代码命名，**`w1` 和 `w3` 是列并行的上投影，`w2` 是行并行的下投影**。PyTorch 的 `parallelize_module` 可根据指定的分片方案执行权重切分和所需通信，自定义 `Linear` 则需要适配内置样式或提供自己的 `ParallelStyle`。 [SwiGLU 实现](../cs336-basics/cs336_basics/swiglu.py#L65) · [PyTorch TP API](https://docs.pytorch.org/docs/stable/distributed.tensor.parallel.html)

### 题目 `tp_calcs`（4 分）

#### （a）给定 \(dy\)，反向传播如何计算？

\(dy\) 的形状为 \((B,D)\)，在各 TP rank 上表示同一份上游梯度。由于 \(y=\sum_i y^{(i)}\)，每份 \(y^{(i)}\) 的梯度都等于 \(dy\)。各 rank 用本地权重分片和已保存的激活计算

\[
\begin{aligned}
dz^{(i)} &= dy\left(W_3^{(i)}\right)^\top,\\
dx_2^{(i)} &= dz^{(i)}\odot f(x_1^{(i)}),\\
dx_1^{(i)} &= dz^{(i)}\odot f'(x_1^{(i)})\odot x_2^{(i)},\\
dW_3^{(i)} &= \left(z^{(i)}\right)^\top dy,\\
dW_2^{(i)} &= x^\top dx_2^{(i)},\\
dW_1^{(i)} &= x^\top dx_1^{(i)},\\
g^{(i)} &= dx_1^{(i)}\left(W_1^{(i)}\right)^\top
          +dx_2^{(i)}\left(W_2^{(i)}\right)^\top,\\
dx &= \operatorname{all\!-\!reduce}_{\mathrm{TP}}\!\left(\{g^{(i)}\}_{i=0}^{p-1}\right).
\end{aligned}
\]

每卡直接得到自己的三个权重梯度分片。\(g^{(i)}\) 是形状为 \((B,D)\) 的输入梯度部分和，各 rank 的贡献相加后得到完整的 \(dx\)。

#### （b）前向和反向分别需要多少 FLOPs？

只计矩阵乘法，每次乘法的三个维度都是 \(B,D,D_{\mathrm{FF}}/p\)。前向有三次矩阵乘法，反向有六次，因此每卡分别需要

\[
\boxed{F_{\mathrm{fwd}}=\frac{6BDD_{\mathrm{FF}}}{p}},
\qquad
\boxed{F_{\mathrm{bwd}}=\frac{12BDD_{\mathrm{FF}}}{p}}.
\]

#### （c）前向和反向分别需要多少通信时间？

前向归约 \(y^{(i)}\)，反向归约 \(g^{(i)}\)，两者均为形状 \((B,D)\) 的 FP16 张量，各占 \(2BD\) 字节。每个阶段都做一次标准环形 all-reduce，所以

\[
\boxed{T_{\mathrm{comm,fwd}}=T_{\mathrm{comm,bwd}}
=4\frac{p-1}{p}\frac{BD}{W}}.
\]

#### （d）前向和反向各允许扩展到多少台设备？

用各阶段的 \(F/C\) 与通信时间比较。前向的条件给出 \(4(p-1)/W\le 6D_{\mathrm{FF}}/C\)，反向则给出 \(4(p-1)/W\le 12D_{\mathrm{FF}}/C\)，所以

\[
\begin{aligned}
\text{前向}\quad &\boxed{N_{\mathrm{TP}}\le 1+\frac{3D_{\mathrm{FF}}W}{2C}},\\
\text{反向}\quad &\boxed{N_{\mathrm{TP}}\le 1+\frac{3D_{\mathrm{FF}}W}{C}}.
\end{aligned}
\]

前向和反向归约相同大小的张量，反向矩阵乘法量是前向的两倍，所以前向先达到通信瓶颈。\(B\) 同时出现在计算量和归约数据量中，化简时被约掉。

## 8.5 二维并行（FSDP + TP）

增加批次大小或模型大小可以提高通信受限前的设备数上限。实际配置还要考虑临界批次大小和缩放定律，因此本题将批次大小、模型大小、带宽和算力视为已给定，求前向保持计算受限所允许的最大设备数。

记 \(p=N_{\mathrm{TP}}\)、\(q=N_{\mathrm{FSDP}}\)，总设备数 \(N=pq\)。设备 \((i,j)\) 与同一个 FSDP rank \(j\) 的其他设备一起处理批次分片 \(x^{(j)}\)，该分片形状为 \((B/q,D)\)。TP 沿中间特征分工，FSDP 沿批次分工，并进一步切分每份 TP 权重，以节省常驻显存。

- **沿 FSDP 轴**固定 \(i\)，从不同 \(j\) 收集权重。\(W_1^{(i,j)},W_2^{(i,j)}\) 从 \((D/q,D_{\mathrm{FF}}/p)\) 收集成 \((D,D_{\mathrm{FF}}/p)\)，\(W_3^{(i,j)}\) 从 \((D_{\mathrm{FF}}/p,D/q)\) 收集成 \((D_{\mathrm{FF}}/p,D)\)。每台卡临时得到当前 TP rank 所需的三份权重。
- **沿 TP 轴**固定 \(j\)。各 TP rank 用 \(x^{(j)}\) 计算自己的中间特征，再用 \(W_3^{(i)}\) 得到形状为 \((B/q,D)\) 的部分输出。对这些部分输出做 all-reduce，得到这份批次的完整输出 \(y^{(j)}\)。

### 题目 `fsdp_tp_calcs`（6 分）

#### （a）二维并行的前向需要多少 FLOPs？

本地的三次矩阵乘法各涉及 \(B/q\)、\(D\) 和 \(D_{\mathrm{FF}}/p\) 三个维度，所以单卡需要

\[
\boxed{F_{\mathrm{fwd}}=\frac{6BDD_{\mathrm{FF}}}{pq}}.
\]

#### （b）两轴通信可重叠时，前向需要多少通信时间？

沿 FSDP 轴需要 all-gather 三份 FP16 TP 权重，总大小为 \(6DD_{\mathrm{FF}}/p\) 字节。沿 TP 轴需要 all-reduce 一个 \((B/q,D)\) 的 FP16 部分输出，大小为 \(2BD/q\) 字节。代入相应的环形公式

\[
\begin{aligned}
T_{\mathrm{FSDP}}&=\frac{q-1}{q}\frac{6DD_{\mathrm{FF}}}{pW}
=\frac{6DD_{\mathrm{FF}}(q-1)}{pqW},\\
T_{\mathrm{TP}}&=2\frac{p-1}{p}\frac{2BD}{qW}
=\frac{4BD(p-1)}{pqW}.
\end{aligned}
\]

两轴的通信完全重叠时，总通信时间为 \(\boxed{T_{\mathrm{comm}}=\max(T_{\mathrm{FSDP}},T_{\mathrm{TP}})}\)。

#### （c）两轴通信可重叠时，设备总数上限是多少？

定义 \(\alpha=BW/C\)、\(\beta=3D_{\mathrm{FF}}W/(2C)\)，并用 \(T_{\mathrm{comp}}=6BDD_{\mathrm{FF}}/(pqC)\) 分别归一化两轴通信时间

\[
\frac{T_{\mathrm{FSDP}}}{T_{\mathrm{comp}}}=\frac{q-1}{\alpha},
\qquad
\frac{T_{\mathrm{TP}}}{T_{\mathrm{comp}}}=\frac{p-1}{\beta}.
\]

因总通信时间取两者的最大值，两个比值都必须不超过 1。因此 \(q\le 1+\alpha\)、\(p\le 1+\beta\)，两轴可以分别取到各自上限。代入 \(N=pq\) 得

\[
\boxed{N\le (1+\alpha)(1+\beta)
=\left(1+\frac{BW}{C}\right)\left(1+\frac{3D_{\mathrm{FF}}W}{2C}\right)}.
\]

实际选择整数并行度时，还要满足该切分方案的均分条件，即 \(q\) 整除 \(B,D\)，\(p\) 整除 \(D_{\mathrm{FF}}\)。

#### （d）两轴共享网络资源时，设备总数上限是多少？

两轴通信耗时相加，保持计算受限的条件变为

\[
\frac{q-1}{\alpha}+\frac{p-1}{\beta}\le 1,\qquad q,p\ge 1.
\]

按题意允许连续并行度。增加任一并行度会增大 \(pq\)，所以最优点满足等号。令 \(u=(q-1)/\alpha\)，则 \(0\le u\le1\)，并且 \(q=1+\alpha u\)、\(p=1+\beta(1-u)\)。代入后

\[
N(u)=(1+\alpha u)\bigl[1+\beta(1-u)\bigr],
\qquad
\frac{dN}{du}=\alpha(1+\beta)-\beta-2\alpha\beta u.
\]

这是开口向下的二次函数。驻点为 \(u_*=(1+\beta^{-1}-\alpha^{-1})/2\)。若 \(u_*\) 在区间内，就取驻点。若越界，就取靠近驻点的端点。设 \(\delta=\alpha^{-1}-\beta^{-1}\)，得到完整上限

\[
\boxed{
N\le
\begin{cases}
1+\beta, & \delta\ge 1,\\[2pt]
\dfrac{(\alpha\beta+\alpha+\beta)^2}{4\alpha\beta}, & -1<\delta<1,\\[6pt]
1+\alpha, & \delta\le -1.
\end{cases}}
\]

中间一种情形满足 \(q/\alpha=p/\beta\)，两轴都参与扩展。两个端点分别对应 \((q,p)=(1,1+\beta)\) 和 \((1+\alpha,1)\)，即把共享带宽全部用于 TP 或 FSDP。

## 9.1 任务目标与实验配置

## 9.2 核心系统优化组合

本实现全部由自有代码组装，不依赖外部 FlashAttention 或 Liger-Kernel 库：

1. **改进版 Triton FlashAttention-2**（[flash_attention_triton_opt.py](../cs336_systems/flash_attention_triton_opt.py)）
   - 放大分块至 `128×64` / `128×128` / `64×128`（精简 4 组 `@triton.autotune` 配置，兼顾吞吐与冷启动编译速度）；
   - 因果掩码下将**完全可见的下三角内部块**与**对角线/边界尾块**拆成独立循环，32K 下 99% 以上的 tile 零索引比较、零 `tl.where`；
   - 前向与两遍无原子反向（`_flash_bwd_dq` / `_flash_bwd_dkv`）全部改用 `tl.make_block_ptr` 并在 B200（SM100）自动启用硬件 **TMA（`tl.make_tensor_descriptor`）**；
   - 内部 softmax 改用 `tl.exp2`（单条硬件 `EX2` 指令），BF16 路径直走原生 Tensor Core MMA。
2. **分块融合 LM Head + Cross-Entropy**（[fused_cross_entropy.py](../cs336_systems/fused_cross_entropy.py)）
   - 避免物化 `[1, 32768, 151936]` 全量 logits（BF16 占 10 GiB，FP32 加反向轻松超过 40~60 GiB）；
   - 按 `chunk_size=2048` 逐块计算 `hidden_chunk @ W^T`（单块仅约 622 MiB），由 Triton 核 `_fused_ce_fwd_bwd_kernel` 在 FP32 寄存器内完成在线 `exp2` logsumexp 并**原地将 `d_logits` 覆写回 logits 缓冲**，在前向阶段即时算出 `d_hidden` 与 FP32 累加的 `d_weight`；
   - `_FusedLMHead` 继承 `cs336_basics.layers.Linear` 并返回延迟句柄，同时无缝兼容 `OverlapDDP` 与 `FSDP` 分片。
3. **仅对 FFN 开启选择性激活重计算 + 叶子算子编译融合**（[leaderboard_model.py](../cs336_systems/leaderboard_model.py)）
   - 32K 上下文下重算 Attention 代价极高，而 SwiGLU 中间激活（`d_ff=11008`）占用显存最大但重算极快；因此采用 `checkpoint_mode="ffn"`，仅对 FFN 子层做激活检查点，**完全不重算 32K FlashAttention**；
   - 34 层共享单份 RoPE 缓存，仅对 `RMSNorm`、`RoPE`、`SwiGLU 门控激活` 3 个无状态叶子函数做 `torch.compile`，冷启动编译开销极低。
4. **Triton 融合版 AdamW**（[fused_adamw.py](../cs336_systems/fused_adamw.py)）
   - 单核一次读入 `(p, g, m, v)` 并在 FP32 寄存器内完成解耦权重衰减与矩更新，再一次写回 `(p, m, v)`，将 HBM 流量降至 7 次读写（物理下限）且零临时显存分配。
5. **两种双卡并行策略对比**（[benchmark_leaderboard.py](../cs336_systems/benchmark_leaderboard.py)）
   - **`ddp_sharded`（ZeRO-1 + 通信重叠）**：`OverlapDDP(gradient_owner=optimizer.parameter_owner)` + `ShardedOptimizer(FusedAdamW)`，权重与梯度在双卡各保留 BF16 副本，优化器状态均摊到两卡，反向通过 `dist.reduce` 异步归约到属主卡并与反向计算重叠，更新后异步 `dist.broadcast` 权重；
   - **`fsdp`（ZeRO-3）**：`FSDP(compute_dtype=torch.bfloat16)` + `FusedAdamW`，所有 `Linear`/`Embedding` 以 FP32 主权重分片存储，前向预取 `all_gather` 转 BF16 计算，反向独立 CUDA Stream 异步 `reduce_scatter` FP32 梯度分片。

两套方案正式计时前均在 rank 0 上以小规模 BF16 因果模型（`ctx_len=128, vocab_size=257, d_model=128, d_ff=384, num_layers=2, num_heads=4`）加载完全相同的初始权重，与 `cs336_basics.TransformerLM` + `cs336_basics.cross_entropy` + `cs336_basics.optim.AdamW` 逐项比对，全部通过：

## 9.5 深入分析：为什么双 B200 上 `ddp_sharded` 全面胜出？

1. **端到端耗时：`ddp_sharded` 更快且波动小 3.4 倍**
   - `ddp_sharded` 中位数比 `fsdp` 快 **94.87 ms/步（2.61%）**，均值快 **101.03 ms/步（2.77%）**，且相对标准差仅 **0.42%**（14.76 ms），而 `fsdp` 达到 **1.38%**（50.22 ms，第 6 步出现 `3753.37 ms` 尖刺）。
   - **通信原因**：当前 `FSDP` 按单个 `Linear` 层做细粒度通信（34 层 × 7 个线性层 + 嵌入/输出头 ≈ 240 次小包通信），前向每次都需要 `all_gather`，反向 `_unpack` 重用权重时又是**同步阻塞 `_gather().wait()`**（尚未实现反向预取），叠加 `reduce_scatter` 的 FP32 转换与归约开销，引入了额外的通信尾延迟；而 `ddp_sharded` 每张卡常驻完整 BF16 权重，**完全省去前向和反向的权重 AllGather**，只有反向异步 `reduce` 与 step 后的异步 `broadcast`。

2. **显存占用：`ddp_sharded` 反而比 `fsdp` 少用 46.6 GiB（allocated）与 47.9 GiB（reserved）**
   这一反直觉现象完全可以通过静态精度与瞬态缓冲精确解释：
   - **`ddp_sharded`（BF16 参数/梯度/分片矩状态，对应题目 `AdamW(model.parameters())`）**：
     - 静态常驻：BF16 权重 `15.14 GiB` + BF16 梯度 `15.14 GiB` + 半份 BF16 `m, v` `15.14 GiB` = **45.41 GiB**（两卡因按整张量贪心分配有轻微不均，rank 0 / rank 1 峰值分别为 `102.71` / `104.89 GiB`）；
     - 激活与临时区：约 **59.5 GiB**（34 层 Attention 激活 + FFN 检查点输入 + 2048-token 分块 CE 缓冲）；
     - `peak_reserved = 128.41 GiB`，距离 B200 的 `178.34 GiB` 仍有约 **50 GiB 安全余量**。
   - **`fsdp`（`compute_dtype=bfloat16`，内部维护 FP32 主权重与 FP32 梯度/优化器分片）**：
     - 静态常驻：半份 FP32 主权重 `15.14 GiB` + 半份 FP32 梯度 `15.14 GiB` + 半份 FP32 `m, v` `30.27 GiB` = **60.54 GiB**（仅精度口径本身就比 BF16 `ddp_sharded` 多 15.1 GiB）；
     - 额外约 **31 GiB** 峰值增量来自 `FSDP` 运行时缓冲：前向预取完整权重、反向 `_reduce_scatter` 将完整层梯度转为 FP32 并挂入 `_pending_gradients` 队列等待 `finish_gradient_synchronization()`，以及 FFN 检查点反向重算期间临时展开的权重副本；
     - 最终 `peak_reserved` 达到 **176.35 GiB**，距 178.34 GiB 仅剩 **2 GiB**，极易触发 PyTorch 缓存分配器的碎片整理与显存回收停顿，这正是 `fsdp` 第 6 步出现 `3753.37 ms` 延迟尖刺和较高标准差的直接原因。

## 9.6 结论与进一步压榨方向

- **当前最佳提交方案**：`ddp_sharded` + `checkpoint_mode="ffn"` + `FlashAttention2TritonOpt`（B200 TMA）+ `FusedLinearCrossEntropy` + `FusedAdamW` + 叶子算子 `torch.compile`，双 B200 实测单步 **3.539 s**（中位数，均值 **3.544 ± 0.015 s**），相比 10 秒基线加速 **2.83×**，冷启动总耗时 **126.9 s**（远低于 600 s 上限）。
- **可继续优化的明确余量**（基于 `ddp_sharded` 仍有 ~50 GiB 空余显存）：
  1. **削减激活重计算层数**：目前 34 层全部开启了 FFN 重计算；利用多余的 ~50 GiB 显存将 `--checkpoint-layers` 降到 `12~16`（甚至测试 `--checkpoint-mode none`），可直接省去一半以上的 FFN 反向重算矩阵乘；
  2. **放大融合 CE 分块与线下锁死 FlashAttention 最优 Tile**：尝试 `--chunk-size 4096`，并通过 `--autotune` 搜出 B200 `D=128, S=32768` 的最佳 tile 后固定配置，进一步压缩单步耗时与 42 s 的首次编译时间；
  3. **若需在更高精度主权重口径下优化 `FSDP`**：可将 `FSDP` 改为按 `TransformerBlock` 粒度聚合通信、补充反向预取，并将梯度规约改为 BF16 `reduce_scatter` 后再转 FP32 累加到主权重分片，以消除 176 GiB 显存逼近上限的问题。
