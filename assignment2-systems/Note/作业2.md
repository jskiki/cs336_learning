**左上：前向时间花在哪些操作上**

每根柱子代表一个模型和上下文长度，总高度为 100%。

- 蓝色：全部矩阵乘法。
- 红色：注意力 softmax。
- 黄色：计算 scores 时的缩放、掩码等非矩阵操作。

**结论：序列越长，softmax、掩码等操作的占比越大。** 这里是前向 kernel 时间的占比，不是 GPU 利用率。

**右上：完整训练时间花在哪个阶段**

将训练 kernel 时间分为前向、反向、优化器更新和损失计算。

**结论：反向占比最大，约为 61%～69%。** 因此只加速前向，整个训练的提速会受到限制。

**左下：medium 的 softmax 内部耗时**

比较长度 1024 和 2048，将 softmax 分成除法、减去最大值、指数、求最大值与求和。

纵轴是**每遍前向跨 24 层累计的 kernel 时间**：从约 **14.40 ms** 增至 **54.60 ms**。

**结论：长度翻倍后，softmax 耗时接近四倍，而且减法、除法也占了不少时间。**

**右下：开启 Nsight 后，整体计时变化多少**

蓝色是仅前向，红色是完整训练。计算方式为：

\[ \frac{\text{采集时墙钟耗时}-\text{普通运行墙钟耗时}} {\text{普通运行墙钟耗时}}\times100\% \]

**结论：短模型对采集更敏感。** 但这些是不同次运行，差值同时包含运行波动，不能全部视为工具开销。

```python
import torch

s1 = torch.tensor(0, dtype=torch.float32)
for i in range(1000):
    s1 += torch.tensor(0.01, dtype=torch.float32)
print(s1)

s2 = torch.tensor(0, dtype=torch.float16)
for i in range(1000):
    s2 += torch.tensor(0.01, dtype=torch.float16)
print(s2)

s3 = torch.tensor(0, dtype=torch.float32)
for i in range(1000):
    s3 += torch.tensor(0.01, dtype=torch.float16)
print(s3)

s4 = torch.tensor(0, dtype=torch.float32)
for i in range(1000):
    x = torch.tensor(0.01, dtype=torch.float16)
    s4 += x.type(torch.float32)
print(s4)
```

这四段代码都执行了 **1000 次累加**。区别在于两件事：**`0.01` 以什么精度保存，以及累加过程以什么精度进行。**

| 情况   | `0.01` 的类型   | 累加器 `s` 的类型 | 结果      |
| ------ | --------------- | ----------------- | --------- |
| 第一段 | FP32            | FP32              | `10.0001` |
| 第二段 | FP16            | FP16              | `9.9531`  |
| 第三段 | FP16            | FP32              | `10.0021` |
| 第四段 | FP16，再转 FP32 | FP32              | `10.0021` |

**第一段：FP32 输入，FP32 累加**

```
s += torch.tensor(0.01, dtype=torch.float32)
```

FP32 不能精确表示 `0.01`，而每次加法也可能产生舍入。1000 次累加后，得到接近 10 的 `10.0001`。

**第二段：FP16 输入，FP16 累加**

```
s += torch.tensor(0.01, dtype=torch.float16)
```

不仅 `0.01` 被近似表示，**每次累加的结果还必须舍入回 FP16**，累计误差明显增大，最终得到 `9.9531`。

例如，FP16 在 `[8, 16)` 范围内，相邻数间隔为 `0.0078125`，所以加上约 `0.01` 后，实际保存的增量可能只有 `0.0078125`。

**第三段：FP16 输入，FP32 累加**

```
s += torch.tensor(0.01, dtype=torch.float16)
```

FP16 保存的 `0.01` 实际约为：

```
0.01000213623046875
```

加法使用 FP32 精度进行，因此这里主要保留的是**输入量化误差**：

\[ 1000\times0.01000213623046875 =10.00213623046875 \]

显示为 `10.0021`，比第二段准确得多。

**第四段：显式转成 FP32 后累加**

```
x = torch.tensor(0.01, dtype=torch.float16)
s += x.type(torch.float32)
```

它与第三段效果相同：第三段在加法中进行类型提升，第四段显式转换。**转换只能保留 FP16 已经存下来的近似值，不能恢复成精确的 `0.01`**，因此结果同样是 `10.0021`。

这个实验说明：**低精度输入配合高精度累加，可以显著减少累加过程中的误差，但无法消除输入在低精度表示时已经产生的误差。**

### 关于混合精度训练的理解

混合精度训练在一些适合降低精度的计算时会降低精度进行计算，以此来达到加速训练的效果，但是模型的参数保存还是以最开始的设置来保存的如float32，（中间的一些结果有的是以低精度保存的如bfloat16）

#### 关于显存的占用

启用混合精度训练后，显存的变化要看两方面

\[ \text{显存净变化} = \text{转换副本等额外开销} - \text{低精度激活节省的空间} \]

“转换副本等额外开销”：为了低精度计算，新增加的张量

低精度激活节省的空间”：中间结果使用更少的字节保存

1. **参数保持原有类型，是因为 autocast 不会永久修改参数的 dtype。** 保存模型时，按参数当时的 dtype 保存；不是保存操作强制使用 FP32。我们初始化为 FP32，所以保存的权重仍是 FP32。

2. **显存公式是简化分析，不是精确的峰值计算公式。** 建议写成：

   \[ \text{显存净变化} \approx \text{额外副本及临时张量占用} - \text{低精度激活节省的空间} \]

   实际还取决于张量同时存在多久、计算图保留哪些结果，以及峰值发生在哪个阶段。
