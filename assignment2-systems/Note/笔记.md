## NVTX

**NVTX 是 NVIDIA 提供的一套标注库/API**，全称是 **NVIDIA Tools Extension**。它让你给代码片段添加名字，方便性能分析工具识别。

在 CUDA 版 PyTorch 中，可以直接使用 `torch.cuda.nvtx` 接口，无需另外安装 Python 的 `nvtx` 包。

最常用的是 `with`：

```python
import torch.cuda.nvtx as nvtx

with nvtx.range("forward"):
    logits = model(inputs)
```

这里：

- 进入 `with` 时，开始一个名为 `forward` 的标注区间。
- 执行区间内的代码。
- 离开 `with` 时，结束该区间。

`nvtx.range` 也可以作为装饰器，标记整个函数。

**标签需要配合 Nsight Systems 才方便查看。** 在已安装 `nsys` 的 GPU 环境中，可以这样启动现有脚本：

```bash
uv run nsys profile \
  --trace=cuda,nvtx \
  --output=results/profile \
  -- python -m cs336_systems.benchmark --device cuda --mode train
```

之后打开生成的 `.nsys-rep` 报告，就能看到 `forward` 区间，以及由这段 CPU 代码发起的 GPU 活动。

| 工具或接口                 | 作用                           |
| -------------------------- | ------------------------------ |
| NVTX                       | 给代码片段添加标签             |
| Nsight Systems             | 采集执行信息，展示时间线和统计 |
| `torch.cuda.synchronize()` | 等待 GPU 完成任务              |



## `torch.autocast` 

的核心规则是：**执行到每个算子时，根据 PyTorch 预先定义的策略选择精度，而不是把整个模型统一转成低精度。**

例如：

```
with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
    y = model(x)
```

这里的 `bfloat16` 指定了**适合低精度执行的算子使用什么类型**，并不代表所有操作都使用 BF16。

**1. 不同算子采用不同策略**

以 CUDA autocast 为例：

| 策略                     | 常见操作                                               | 行为                                |
| ------------------------ | ------------------------------------------------------ | ----------------------------------- |
| 使用指定的低精度         | `linear`、`matmul`、`mm`、`bmm`、卷积                  | 将适用的浮点输入转换为 FP16 或 BF16 |
| 使用 FP32                | `layer_norm`、`softmax`、`exp`、`sum`、`cross_entropy` | 将适用的输入提升为 FP32             |
| 按最宽输入类型执行       | `addcmul`、`tensordot` 等                              | 输入中有 FP32，就统一使用 FP32      |
| 没有专门的 autocast 规则 | 如普通 ReLU                                            | 按算子自身的类型规则处理输入        |

普通加法等操作本身也有类型提升规则，不需要 autocast 介入。[官方算子列表](https://docs.pytorch.org/docs/2.11/amp.html#cuda-op-specific-behavior)

**2. 模型参数本身仍然是 FP32**

假设权重原本是 FP32，执行线性层时，可以理解为：

```
原始 FP32 输入、FP32 权重
          ↓ 为本次计算转换
      BF16 输入、BF16 权重
          ↓ 矩阵乘法
         BF16 输出
```

**原始参数没有被永久改成 BF16**，后续遇到需要 FP32 的算子时，又可以使用 FP32 计算。因此通常不需要提前调用 `model.half()` 或 `model.bfloat16()`。[官方说明](https://docs.pytorch.org/docs/2.11/amp.html#autocasting)

**3. 精度可以在网络中来回变化**

以题目的 ToyModel 为例，在 CUDA FP16 autocast 下，典型的数据流是：

```
FP32 输入
   ↓ Linear
FP16
   ↓ ReLU
FP16
   ↓ LayerNorm
FP32
   ↓ Linear
FP16 logits
   ↓ 官方 cross_entropy（也在 autocast 区间内）
FP32 loss
```

退出 `with` 后，**已经生成的输出不会自动转回 FP32**。

**4. 有些写法不会触发自动转换**

以下情况尤其要注意：

- **原地操作**，例如 `exp_()`、`add_()`，不会经过 autocast 的自动转换。
- 使用 `out=...` 的操作不会经过自动转换。
- 显式传入 `dtype=...` 时，遵循你指定的类型。
- 整数、布尔类型及 FP64 不会被自动降成 FP16/BF16。[适用条件](https://docs.pytorch.org/docs/2.11/amp.html#op-eligibility)

所以，**我们自己写的 `softmax` 不会因为函数叫这个名字，就自动全部使用 FP32**；autocast 看的是它内部实际调用的 PyTorch 算子。例如，我们的 `exp_()` 是原地操作，其行为就不同于官方列出的 `exp()`。

**5. 反向传播与损失缩放是另外两件事**

通常把前向和损失计算放在 autocast 中，在区间外调用 `loss.backward()`；反向按对应前向运算确定的精度路径执行，原始 FP32 参数的 `.grad` 通常仍为 FP32。`autocast` 本身不做损失缩放，FP16 训练通常还会搭配 `GradScaler`。



LayerNorm 中均值与方差的归约计算容易积累舍入误差，减去均值及对较小方差求倒数平方根也可能使误差更明显，因此通常使用 FP32 计算这些部分。改用 BF16 后仍需要关注这些问题：它虽然具有与 FP32 相同的指数范围，但有效精度更低，不能消除舍入误差；CUDA autocast 对官方 `layer_norm` 仍采用 FP32 策略。





### `nullcontext()`

 是一个**什么也不做的上下文管理器**，让关闭混合精度时，也能使用同一段代码。

这句代码的意思是：

```python
with (
    torch.autocast(device_type=inputs.device.type, dtype=torch.bfloat16)
    if mixed_precision
    else nullcontext()
):
    logits = model(inputs)
```

- `mixed_precision=True`：进入 `autocast`，按混合精度规则计算。
- `mixed_precision=False`：进入 `nullcontext()`，直接按原有精度计算。

这样就不用为开启、关闭混合精度分别复制一份前向代码。

注意，`nullcontext()` **不会主动关闭外层的 autocast**；它只是没有额外操作。我们当前没有外层 autocast，因此关闭开关时就是原来的 FP32 路径。

### 什么是上下文管理器

上下文管理器是 Python 中用来管理“一段代码执行前后要做什么”的机制，通常配合 `with` 使用。

执行过程可以理解为：

```
进入 with：执行准备操作
    ↓
执行 with 内缩进的代码
    ↓
退出 with：执行收尾操作，即使中间出现异常也会处理退出
```

例如，打开文件：

```
with open("note.txt", "r") as f:
    text = f.read()
```

进入时打开文件，退出时自动关闭文件。

你现在遇到的几个例子也是同样的结构：

| 上下文管理器            | 进入时                 | 退出时           |
| ----------------------- | ---------------------- | ---------------- |
| `torch.autocast(...)`   | 启用指定的混合精度规则 | 恢复进入前的设置 |
| `torch.no_grad()`       | 关闭梯度记录           | 恢复进入前的设置 |
| `nvtx.range("forward")` | 标记区间开始           | 标记区间结束     |
| `nullcontext()`         | 不做额外操作           | 不做额外操作     |

所以，`with` 中的缩进范围，就是这些设置或资源管理规则生效的范围。

### nullcontext()` **不会主动关闭外层的 autocast**；它只是没有额外操作。我们当前没有外层 autocast，因此关闭开关时就是原来的 FP32 路径。

意思是：**`nullcontext()` 不会改变当前设置，外面是什么状态，里面就保持什么状态。**

我们当前的代码没有外层 autocast：

```
# 当前没有开启 autocast
with nullcontext():
    logits = model(inputs)  # 保持原来的 FP32 路径
```

但如果外面已经开启了 autocast：

```
with torch.autocast("cuda", dtype=torch.bfloat16):
    with nullcontext():
        logits = model(inputs)  # 外层 autocast 仍然生效
```

这里 `nullcontext()` 没有执行任何关闭操作，所以仍使用混合精度规则。

**你现在的代码没有第二种嵌套情况，因此直接理解成：开关打开用混合精度，关闭就保持原来的 FP32 即可。**





量化可以从几个不同维度分类。**这些分类能组合使用：INT4 是数值格式，PTQ 是量化时机，GPTQ 是具体算法，它们并不是互斥的方案。**

**1. 按什么时候量化：PTQ 与 QAT**

| 方式                  | 做法                                               | 特点                                     |
| --------------------- | -------------------------------------------------- | ---------------------------------------- |
| **PTQ：训练后量化**   | 模型训练完成后，再转换权重和适用的激活             | 通常不需要重新训练，部分方法需要校准数据 |
| **QAT：量化感知训练** | 训练或微调时模拟量化误差，结束后转换成实际量化模型 | 让权重提前适应低精度表示，但需要额外训练 |

QAT 中常见的“伪量化”会模拟舍入、截断等误差，**张量和计算本身仍可能是浮点精度**，不代表训练时已经获得实际的 INT4 存储节省。[PyTorch QAT 说明](https://docs.pytorch.org/ao/stable/api_reference/generated/torchao.quantization.qat.QATConfig.html)

**2. 按量化什么：权重、激活与缓存**

常见写法中的 **W 是权重，A 是激活，数字表示位数**：

| 写法              | 含义                                     |
| ----------------- | ---------------------------------------- |
| **W4A16**         | 4-bit 权重，16-bit 激活                  |
| **W8A16**         | 8-bit 权重，16-bit 激活                  |
| **W8A8**          | 权重和激活都是 8-bit                     |
| **KV Cache 量化** | 降低推理过程中保存的 Key、Value 缓存精度 |

只量化权重通常称为 **weight-only quantization**。这些写法没有完整说明具体数值格式、累加精度，也不意味着模型每一层都使用相同精度。[torchao 支持的组合](https://docs.pytorch.org/ao/stable/workflows/inference.html)

**3. 按数值表示：INT、FP 与码本**

| 格式           | 基本方式                                                     |
| -------------- | ------------------------------------------------------------ |
| **INT8、INT4** | 用低位整数表示，通常配合缩放系数和零点                       |
| **FP8**        | 8-bit 浮点数，例如 E4M3、E5M2，通常也需要缩放                |
| **FP4**        | 4-bit 浮点表示，依赖相应的低精度实现                         |
| **NF4**        | 16 个非均匀代表值组成的 4-bit 码本，针对近似正态分布的权重设计 |

所以，**“4-bit 模型”不一定是 INT4，也可能是 NF4 或 FP4**。[NF4 原论文](https://arxiv.org/abs/2305.14314)

MXFP8、NVFP4 等名称还包含特定的分块缩放规则，不仅仅指定每个数值占几位。[NVIDIA 说明](https://docs.nvidia.com/deeplearning/transformer-engine/examples/fp8_primer.html)

**4. 按量化参数的共享范围：量化粒度**

| 粒度                      | 缩放参数如何共享                                  |
| ------------------------- | ------------------------------------------------- |
| **Per-tensor**            | 整个张量共用一组                                  |
| **Per-channel**           | 每个通道单独一组，例如线性层的每个输出通道        |
| **Per-group / Per-block** | 将权重分组或分块，每组单独一组，例如每 128 个权重 |
| **Per-token**             | 每个 token 的激活向量单独一组                     |

更细的粒度通常能更好地适应不同位置的数值范围，但需要更多缩放信息和相应的 kernel 支持。[量化粒度说明](https://docs.pytorch.org/ao/stable/contributing/quantization_overview.html)

**5. 按映射和缩放参数的确定方式**

整数仿射量化通常近似表示为：

\[ \hat w=s(q-z) \]

- **对称量化**：围绕零对称映射；有符号整数量化中通常令零点 \(z=0\)。
- **非对称量化**：允许零点偏移，更灵活地覆盖偏向一侧的分布。
- **静态量化**：适用的缩放参数提前通过校准等方式确定。
- **动态量化**：运行时根据当前输入计算量化参数，常用于激活。

“动态”通常不是说每次重新量化整个模型，而是指某些张量的量化参数随输入变化。[PyTorch 原理说明](https://pytorch.org/blog/quantization-in-practice/)

**6. 常见具体方法：这些名字分别是什么**

| 名称            | 属于什么               | 核心思路                                                     |
| --------------- | ---------------------- | ------------------------------------------------------------ |
| **GPTQ**        | 训练后权重量化算法     | 利用近似二阶信息补偿量化误差。[论文](https://arxiv.org/abs/2210.17323) |
| **AWQ**         | 激活感知的权重量化方法 | 利用激活统计，通过通道缩放保护重要权重。[论文](https://arxiv.org/abs/2306.00978) |
| **SmoothQuant** | 权重与激活量化方法     | 用等价缩放缓解激活异常值问题，帮助实现 W8A8。[论文](https://arxiv.org/abs/2211.10438) |
| **QLoRA**       | 量化模型上的微调方法   | 冻结低位基础权重，训练额外的 LoRA 参数。[论文](https://arxiv.org/abs/2305.14314) |

例如，一个方案可以描述成：

> **训练后使用 GPTQ，将权重做成 INT4、每组 128 个权重共享量化参数，激活使用 BF16。**
